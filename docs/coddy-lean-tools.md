# Проверки Lean в Coddy

## Настройка

Поддерживается проверенный адаптер Coddy Agent 1.2.54. В доверенный внешний профиль добавляются поля:

```json
{
  "tools": ["check_lean"],
  "tool_proxy": "/absolute/path/to/research-server"
}
```

Это часть `external`, а не отдельный профиль. `tool_proxy` указывает на собранный сервер этого проекта. В `limits.max_tool_calls` нужно указать 1..4. Для задания контрпримеров можно выбрать `check_refutation`; другие имена отклоняются. Инструменты внешнего процесса закрепляются шаблоном сервера и не редактируются браузером.

Для профиля без этих полей сохранен режим вопросов Coddy. MCP-инструменты в нем недоступны. Профиль с проверками запускается в режиме планирования с режимом разрешений `ask`. Проектные MCP-серверы, правила, навыки, подчиненные агенты и обработчики событий автоматически не загружаются.

## Передача вызова

1. Сервер закрепляет формальную цель и опубликованные зависимости по снимку попытки.
2. Для попытки создается закрытый Unix-сокет и список доверенных обработчиков.
3. Через ACP `session/new` передается один стандартный MCP-сервер. Его дочерняя программа передает JSON-RPC через сокет; ключ модели ей не передается.
4. Модель вызывает `research__check_lean` либо `research__check_refutation`. Аргументом служит только исходник кандидата до 64000 байт; изменить цель, каталог или настройки компилятора нельзя.
5. Сервер последовательно проверяет исходник в закрепленной среде Lean без сети. На проверку отводится до 60 секунд, на попытку до четырех проверок.
6. Отчет и исходник сохраняются в `attempts/{id}/toolchecks`. Ошибка компиляции возвращается исполнителю для исправления. Промежуточный успех не заменяет итоговую проверку, рецензию и решение оператора.

Разрешение ACP дается только одному вызову с точным именем зарегистрированной проверки. Запросы разрешения команд и прочих операций отклоняются. Контейнеру не подключается сокет Docker; файл задания доступен только для чтения. В контейнере используются нейтральные пути `/research/home` и `/research/workspace`.

Режим планирования Coddy также показывает встроенные средства чтения и поиска. Адаптер не превращает набор инструментов Coddy в список из двух функций. Контейнер ограничивает файловые подключения, но имеет сетевой доступ для поставщика модели; отдельное ограничение исходящих адресов не реализовано. Для недоверенных материалов предпочтителен собственный исполнитель с явным списком инструментов.

## Местное испытание

```sh
CODDY_AGENT_TEST_BINARY=/path/to/coddy-agent \
RESEARCH_TEST_LEAN_CONFIG=/path/to/private-lean.json \
  go test -race ./internal/researchweb -run TestCoddyLeanToolBDD -count=1
```

Используются настоящий Coddy, местная подстановка ответов модели и указанная среда Lean. Сценарий требует ошибку первого файла, получение диагностики, исправление второго файла, две сохраненные проверки и отсутствие автоматической приемки. Учетные данные поставщика не нужны.
