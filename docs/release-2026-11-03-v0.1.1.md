# Релиз v0.1.1

## Изменения

- Добавлены 256-битные вычисления и построчное возобновление `scripts/near_binary_bfs.py`.
- Для `r=6` при `9≤n≤20` вычислительно подтверждено `D=n−2`.
- Для `r=7` при `n=12,14,15,16,17` подтверждено `D=n−1`; для `n=10,11,13` подтверждено `D=n−2`.
- Для `r=8` сохранены `D(11)=10`, `D(12)=11`, `D(13)=12` и `D(14)=14`; случай `n=15` вычисляется.
- Настроено кэширование закрепленного архива Lean в CI.
- Выполнен успешный smoke с белым списком: `run-ffcddf9aed22cca97773bf4ba8e3801f` вернул корректный JSON и прошел Lean.
- Четырехпрофильная абляция baseline/logika/TRIZ/TOC дала одинаковый корректный исходник, все четыре кандидата прошли Lean.

## Проверки

- `go test -race ./...`, `go vet ./...`, `go build ./...`.
- CI с кэшем Lean, включая Go, web и research-artifacts.
- `scripts/check-research-artifacts.sh` для `r=2..5` до `n=32`.
- `scripts/check-near-binary-extended.sh` для `r=2..5` до `n=40`.
- Все четыре кандидата абляции имеют `verified` с разрешенными `propext` и `Quot.sound`.

## Ограничения

Все формулы диаметра `r=2…8` являются вычислительными гипотезами, а не общими доказательствами. Одна общая задача абляции не показывает устойчивого преимущества навыков; дополнительные поля JSON у logika, TRIZ и TOC делают baseline чище по контракту. Релиз не включает доказательство `D=n−2` для `r=6` или `D=⌈n/3⌉` для `r=2`.
