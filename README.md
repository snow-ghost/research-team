# Research Team

Минимальная рабочая версия исследовательской команды: веб-интерфейс, сервер на Go, исполнители заданий и подключение процесса Coddy Bot через GitHub.

Интерфейс работает с серверной базой PostgreSQL: исследования, гипотезы, задания, попытки, вопросы, рецензии и версии оснований. SQLite сохранена для прежних рабочих областей и быстрых проверок; предусмотрен перенос в PostgreSQL.

Оператор может разрешить отдельный запуск, ограниченный цикл или команду с заданиями поиска доказательства, проверки контрпримеров, формализации и рецензии. Планировщик предлагает леммы, покрытие и исследовательские приемы; ветви запускаются после подтверждения оператора. Проверяющая служба Lean сверяет кандидат с закрепленной формальной целью; решение о приемке остается за оператором.

## Быстрый запуск

Для Go-команд нужен Go 1.26 или новее. Работа с внешними агентами и защищенным каталогом состояния рассчитана на Linux. Команды выполняются из корня репозитория.

```sh
go test ./...
go run ./cmd/research-team
go run ./cmd/research-agent -config examples/agents/model.json
```

Последняя команда проверяет профиль без запуска модели и чтения токена. Примеры содержат заменяемые адреса, модели и пути программ. `-execute` разрешает исполнение и возможные расходы поставщика. Относительный `workspace` в задании разрешается относительно файла задания.

Веб-интерфейс и сервер, Node.js 24, Go 1.26 и Docker Compose:

```sh
go run ./cmd/research-db -init-local
docker compose --env-file .env.postgres up -d postgres
cd web-research-demo
npm ci
npm run build
cd ..
./scripts/run-postgres.sh
```

Адрес: <http://127.0.0.1:4187/>. Сервер сообщает путь к файлу ключа входа, но не печатает сам ключ. При занятом порте измените поле `listen` в конфигурации. База находится в томе Compose, файлы попыток и ключ остаются в `.research-server/`. PostgreSQL доступен на `127.0.0.1:55433`.

При существующей SQLite сначала выполните [перенос](docs/postgres.md#перенос-sqlite). Пароли в `.env.postgres` создаются один раз и не входят в Git. Вариант без PostgreSQL: `go run ./cmd/research-server -config examples/server/local.json`.

Профили в примере требуют настройки модели, переменных окружения или программ исполнителей. Без этих настроек оплачиваемые обращения не выполняются. Порядок подключения, границы изоляции и настройки Coddy описаны в [инструкции сервера](internal/researchweb/README.md).

Учебный режим доступен по адресу <http://127.0.0.1:4187/?demo=1>. Он работает с отдельными данными браузера и не запускает агентов.

## Проверки

Используется BDD: сценарии поведения находятся в [features](features), исполняемые проверки Go в файлах `*_bdd_test.go`. Автоматического сопоставления шагов Gherkin нет.

```sh
go test -race ./...
go vet ./...
go build ./...
```

Из каталога `web-research-demo`:

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:mvp
```

Браузерные проверки сами запускают местные серверы. `test:e2e` проверяет учебный режим; `test:mvp` собирает и запускает настоящий Go-сервер с местными подстановками модели и GitHub. Учетные данные поставщиков не нужны. `DEMO_URL` задает адрес готового учебного экземпляра; `CHROME_PATH` задает путь браузера. GitHub Actions запускает PostgreSQL для проверок Go и сквозных сценариев. [Настройка отдельных тестовых баз](docs/postgres.md#проверки).

Для проверки настоящего Coddy Agent требуется отдельно собранный файл закрепленной версии. Испытание использует местную подстановку модели, а не оплачиваемый сервис:

```sh
CODDY_AGENT_TEST_BINARY=/path/to/coddy-agent CODDY_AGENT_TEST_VERSION=1.2.54 \
  go test -race ./internal/execution -run CoddyAgentBDD -count=1
```

Порядок сборки и ограничения приведены в [инструкции Coddy Agent](integrations/coddy/AGENT.md).

## Границы реализации

- Навыки задают процедуры; права на инструменты и файлы задает программа.
- Внешний агент требует изоляции ОС и сети. `operator_managed` не создает контейнер.
- Токены передаются через окружение, а не через задание или сохраняемый профиль.
- Полный процесс Coddy Bot требует отдельного развертывания и испытания в выбранном репозитории.
- Сервер рассчитан на одного оператора и локальный адрес. Разграничение пользователей, TLS и размещение в открытой сети не реализованы.
- Команда ограничивает число попыток и обрабатывает заданное дерево. Журнал сохраняет видимые действия; внутренние рассуждения модели не запрашиваются. Общий денежный бюджет, автоматический выбор гипотез, разграничение нескольких операторов и независимая оценка качества исследовательских стратегий остаются задачами развития.
- Удаленные исполнители и Telegram требуют явной настройки и включения для исследования. Примеры не содержат действующих учетных данных.

Публичный репозиторий содержит код, учебные данные и инструкции. Личная база знаний, настройки Obsidian, состояние исполнителей и результаты местных запусков в него не входят. [Сторонний код](THIRD_PARTY_NOTICES.md).
