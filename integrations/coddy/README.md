# Развертывание Coddy для исследовательской команды

Выбран полный процесс Coddy: задача GitHub, план, работа агента, отправка изменений, запрос на слияние и обработка замечаний. [Соединитель Go](../../internal/coddy/README.md) работает с этим процессом через GitHub API. Он не запускает `worker --once` и не изменяет файлы очереди Coddy.

## Закрепленная версия

Исходники: [coddy-project/coddy-bot](https://github.com/coddy-project/coddy-bot), фиксация `fc3b9491d76d5911aa78e51fc6494ddf3c21bb77`.

В этой версии вызов `commit_all_and_push` в `review_loop.py` не передает обязательные аргументы ветви и автора. Исключение перехватывается, после чего функция может вернуть `success`. [Место вызова](https://github.com/coddy-project/coddy-bot/blob/fc3b9491d76d5911aa78e51fc6494ddf3c21bb77/coddy/worker/review_loop.py#L119), [сигнатура функции](https://github.com/coddy-project/coddy-bot/blob/fc3b9491d76d5911aa78e51fc6494ddf3c21bb77/coddy/services/git/push_pull.py#L47)

Подготовлена [поправка review-loop-v1](patches/review-loop-v1.patch): передаются ветвь, сообщение и данные автора; отсутствие автора и ошибка отправки дают `failed`. Поправка не устраняет остальные ограничения Coddy и не доказывает работоспособность всего развертывания.

Из корня этого репозитория проверить применимость в подготовленном каталоге исходников Coddy:

```sh
RESEARCH_ROOT="$PWD"
git -C "$CODDY_SOURCE" rev-parse HEAD
git -C "$CODDY_SOURCE" apply --check \
  "$RESEARCH_ROOT/integrations/coddy/patches/review-loop-v1.patch"
```

После проверки точной версии применить:

```sh
git -C "$CODDY_SOURCE" apply \
  "$RESEARCH_ROOT/integrations/coddy/patches/review-loop-v1.patch"
```

Эта команда изменяет только `coddy/worker/review_loop.py`. Наши испытания применяют поправку к временной копии; изученный исходный каталог не менялся.

Параметры `coddy_revision` и `coddy_patchset` в соединителе фиксируют заявленное развертывание. GitHub не сообщает версию работающего Coddy; эти поля не заменяют проверку образа или среды оператором.

## Среда и полномочия

Подготовить отдельную изолированную среду Python с зависимостями Coddy и выбранным ACP-агентом. Версии зависимостей и программы агента должны быть закреплены после испытания совместимости. Установка и вызов реальной модели в этой работе не выполнялись.

Использовать отдельный закрытый репозиторий для опытов. Учетная запись Coddy должна иметь права работы с задачами, отправки изменений и создания запросов на слияние только в нем. Учетная запись соединителя должна отличаться от Coddy: комментарии от самого бота Coddy игнорирует.

[Пример настроек](config.example.yaml) содержит заменяемые значения. Репозиторий, `bot.username` и `default_branch` должны совпасть с настройками соединителя. `bot.name` и `bot.email` обязательны для отправки исправлений. `workspace_path` указывает отдельную копию целевого репозитория с настроенной аутентификацией Git.

Секреты Coddy передаются через защищенное окружение или поддержанные файлы секретов:

- `GITHUB_TOKEN` или `GITHUB_TOKEN_FILE`;
- `WEBHOOK_SECRET` или `WEBHOOK_SECRET_FILE`;
- учетные данные модели, требуемые выбранным ACP-агентом.

`RESEARCH_GITHUB_TOKEN` соединителя не следует передавать процессу Coddy. Рабочий каталог и копия репозитория не должны содержать файлы секретов.

ACP-клиент Coddy наследует окружение и предоставляет агенту инструменты. Разделение учетных записей, файловой системы и сетевых направлений задается средой ОС; настройки приложения не заменяют изоляцию.

## Процессы и события

Для запуска Coddy Agent внутри этого процесса подготовлены [отдельная инструкция](AGENT.md), [настройки бота](config.coddy-agent.example.yaml) и [настройки агента](agent.example.yaml). Имя программы и каталог состояния агента отделены от Coddy Bot. Это дополнительный выбор ACP-исполнителя, а не замена соединителя GitHub.

В подготовленной среде проверить конфигурацию:

```sh
python -m coddy observer --config /etc/research-coddy/config.yaml --check
python -m coddy worker --config /etc/research-coddy/config.yaml --check
```

После настройки секретов, репозитория и изоляции служба управления процессами запускает два отдельных процесса:

```sh
python -m coddy observer --config /etc/research-coddy/config.yaml
python -m coddy worker --config /etc/research-coddy/config.yaml
```

Они используют один каталог Coddy; для начального развертывания нужен один работник. Параллельная обработка независимыми работниками с общим каталогом не проверена.

В GitHub включаются события `issues`, `issue_comment`, `pull_request`, `pull_request_review` и `pull_request_review_comment` для адреса обработчика `/webhook/github`. Перед ним требуется HTTPS; пример настроек слушает только адрес обратной связи. Нужны проверка подписи по `WEBHOOK_SECRET`, наблюдение за доставкой событий и контроль доступности обоих процессов.

Первое назначение вызывает подготовку плана. Подтверждение плана запускает разработку и разрешает предусмотренные Coddy действия публикации. Для рецензии нужны замечания к строкам; один общий текст рецензии его работник не использует как перечень исправлений.

Доступ на запись комментариев должен быть ограничен доверенными участниками: изученная версия Coddy распознает фразы согласия в комментариях, а не подпись решения исследовательского координатора. Даже отрицательное предложение с таким словом может быть принято как согласие. Соединитель защищает свой путь публикации; он не запрещает действия напрямую в GitHub.

## Остановка

`research-coddy -action hold` запрещает новые действия соединителя, но не отменяет уже работающую задачу. Для остановки Coddy оператор останавливает оба процесса и принадлежащие им агенты через управляющую службу, затем сверяет GitHub и ожидающие публикации. Остановка одного работника не блокирует наблюдателя.

Автоматическое удаление ветвей, закрытие запросов на слияние и отмена оплачиваемых обращений не выполняются. История уже сделанных публикаций сохраняется.

## Проверка в рабочей среде

До использования с исследовательскими материалами нужен отдельный опыт в тестовом репозитории: создать малую задачу, дождаться плана, подтвердить его, получить запрос на слияние, отправить замечание к строке, подтвердить исправление и проверить новый хеш. После этого проверить остановку обоих процессов, потерю связи и отсутствие повторной публикации.

Этот опыт здесь не проводился: репозиторий назначения, учетные записи и секреты не предоставлены. Выполнены проверки соединителя на местном сервере и проверки поправки с подставными зависимостями.
