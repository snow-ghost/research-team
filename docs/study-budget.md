# Общий бюджет исследования

Бюджет действует для всех частей одного исследования: команд, отдельных циклов, местных и удаленных заданий. Предел команды остается дополнительным ограничением. Новая команда, смена представления или исполнителя не сбрасывает историю попыток.

Оператор задает бюджет через `POST /api/studies/{id}/budget` или форму «Настроить бюджет»:

```json
{
  "expected_revision": 42,
  "request_id": "budget-command-001",
  "confirm": true,
  "note": "Разрешен один дополнительный цикл проверки",
  "budget": {
    "max_attempts": 12,
    "max_output_tokens": 120000,
    "deadline_at": "2026-10-06T12:00:00Z"
  }
}
```

`max_attempts` учитывает все зарегистрированные попытки, включая отмененные и неуспешные. Допустимый диапазон: 1..100. `max_output_tokens=0` отключает общий предел выходных токенов; сроки и число попыток продолжают действовать. До настройки бюджета сохраняется прежнее поведение. Изменение требует отдельного подтверждения и отсутствия действующих попыток. Основание сохраняется в `budget.operator_note`, команда и ее контрольная сумма входят в журнал.

Перед назначением программа резервирует `max_output_tokens * max_steps` выбранного профиля. Параметры попытки закреплены при регистрации. Резервы одновременных частей складываются в транзакции. Известный полный расход освобождает неиспользованную часть резерва. При неизвестном или неполном расходе резерв остается занятым. Отмененная до начала попытка освобождает резерв и сохраняется в числе попыток.

Историческое обращение с неизвестным расходом и без закрепленного резерва блокирует настройку общего токенного предела. Система не подменяет неизвестный расход нулем или оценкой по текущему профилю. Для такого исследования доступны предел попыток и срок; общий токенный предел проверяют в новом исследовании с полной историей резервов.

Механизм ограничивает назначение новых запросов по числу попыток и выходным токенам. Денежный предел и входные токены в это ограничение не входят. Соблюдение параметров сторонним поставщиком проверяется по его отчетам; гарантии принудительной остановки на стороне поставщика нет. Расход удаленного исполнителя учитывается по переданным им счетчикам, без независимой проверки оплаты. Диагностические программы вне сервера имеют отдельные пределы и журнал; сервер их автоматически не учитывает.

При истечении срока новые попытки запрещены. Планировщик отменяет очереди и запрашивает остановку местных процессов. Аренда удаленного задания не выходит за срок исследования; просроченные продления и результаты отклоняются при проверке запроса. Остановка модели на стороне поставщика при отмене не считается подтвержденной.

`GET /api/studies/{id}/observability` содержит `budget`: число попыток, известные выходные токены, удержанный расход, резерв действующих заданий, неизвестный расход и достижение срока. `attempt.stop_cause` различает подтвержденный предел токенов, предел байтов, срок попытки, срок исследования, ошибку ACP или транспорта и неуточненное ограничение. Отсутствие счетчиков не дает основания называть ограничение токенным.

Автоматическая смена исполнителя и автоматическое повышение квоты не добавлены. Оператор выбирает новый профиль отдельным заданием или разрешает продолжение команды. Предыдущие ошибки, версии целей и авторство сохраняются.

## Рецензия зарегистрированного исходника

`POST /api/attempts` принимает необязательное `review_verification`. Для задания вида `review` оно указывает действительную проверку текущей версии. Рецензент получает исходник, цель, автора и отчет Lean в `review_materials`; попытка хранит `proof_binding` с идентификатором проверки и контрольными суммами. Чужая цель, неуспешная проверка, устаревшая версия и совпадающий автор отклоняются.

Для отдельно зарегистрированного файла рецензию и поиск контрпримеров выполняют до прикрепления доказательства: прикрепление повышает версию. Затем прикрепляют проверку, связывают результат и отдельно принимают его. Исправленный файл требует новой проверки и новой рецензии. Старые версии не принимаются по совпадению математического смысла.
