# Research Team

Минимальная рабочая версия исследовательской команды: веб-интерфейс, сервер на Go, исполнители заданий и подключение процесса Coddy Bot через GitHub.

Интерфейс работает с серверной базой SQLite: исследования, гипотезы, задания, попытки, вопросы, рецензии и версии оснований. Запуск исполнителя требует подтверждения оператора. Полученный материал остается кандидатом до отдельного решения о приемке. Автономный выбор исследовательской стратегии и формальная проверка доказательств не реализованы.

## Быстрый запуск

Для Go-команд нужен Go 1.26 или новее. Работа с внешними агентами и защищенным каталогом состояния рассчитана на Linux. Команды выполняются из корня репозитория.

```sh
go test ./...
go run ./cmd/research-team
go run ./cmd/research-agent -config examples/agents/model.json
```

Последняя команда проверяет профиль без запуска модели и чтения токена. Примеры содержат заменяемые адреса, модели и пути программ. `-execute` разрешает исполнение и возможные расходы поставщика. Относительный `workspace` в задании разрешается относительно файла задания.

Веб-интерфейс и сервер, Node.js 24 и Go 1.26:

```sh
cd web-research-demo
npm ci
npm run build
cd ..
go run ./cmd/research-server -config examples/server/local.json
```

Адрес: <http://127.0.0.1:4187/>. Сервер сообщает путь к файлу ключа входа, но не печатает сам ключ. При занятом порте измените поле `listen` в конфигурации. Рабочие данные по умолчанию сохраняются в `.research-server/`.

Профили в примере требуют настройки модели, переменных окружения или программ исполнителей. Без этих настроек оплачиваемые обращения не выполняются. Порядок подключения, границы изоляции и настройки Coddy описаны в [инструкции сервера](internal/researchweb/README.md).

Учебный режим доступен по адресу <http://127.0.0.1:4187/?demo=1>. Он работает с отдельными данными браузера и не запускает агентов.

## Проверки

Используется BDD: сценарии поведения находятся в [features](features), исполняемые проверки Go в файлах `*_bdd_test.go`. Автоматического сопоставления шагов Gherkin нет.

```sh
go test -race ./...
go vet ./...
go build ./...
```

Из каталога `web-research-demo`:

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:mvp
```

Браузерные проверки сами запускают местные серверы. `test:e2e` проверяет учебный режим; `test:mvp` собирает и запускает настоящий Go-сервер с местными подстановками модели и GitHub. Учетные данные поставщиков не нужны. `DEMO_URL` задает адрес готового учебного экземпляра; `CHROME_PATH` задает путь браузера. GitHub Actions выполняет обе группы.

Для проверки настоящего Coddy Agent требуется отдельно собранный файл закрепленной версии. Испытание использует местную подстановку модели, а не оплачиваемый сервис:

```sh
CODDY_AGENT_TEST_BINARY=/path/to/coddy-agent \
  go test -race ./internal/execution -run CoddyAgentBDD -count=1
```

Порядок сборки и ограничения приведены в [инструкции Coddy Agent](integrations/coddy/AGENT.md).

## Границы реализации

- Навыки задают процедуры; права на инструменты и файлы задает программа.
- Внешний агент требует изоляции ОС и сети. `operator_managed` не создает контейнер.
- Токены передаются через окружение, а не через задание или сохраняемый профиль.
- Полный процесс Coddy Bot требует отдельного развертывания и испытания в выбранном репозитории.
- Сервер рассчитан на одного оператора и локальный адрес. Разграничение пользователей, TLS и размещение в открытой сети не реализованы.
- Распределенная очередь, общий денежный бюджет, автоматический выбор гипотез, поток промежуточных действий агента и формальная математическая приемка остаются задачами развития.

Публичный репозиторий содержит код, учебные данные и инструкции. Личная база знаний, настройки Obsidian, состояние исполнителей и результаты местных запусков в него не входят. [Сторонний код](THIRD_PARTY_NOTICES.md).
