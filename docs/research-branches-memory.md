# Ветви, проверки Lean и память

## Управление исследованием

Во вкладке «Задания» форма команды допускает отдельную команду и ветвь исследования. Ветвь содержит цель, прием, основание выбора, приоритет 0..100 и закрепленные профили четырех ролей. Создание требует подтверждения оператора.

Сервер выбирает ожидающие ветви по убыванию приоритета. Одновременно работает одна команда или один отдельный цикл на исследование. Между исследованиями действует `max_parallel`. Команда использует существующее дерево обязательств. Предложение разбиения агентом и подтверждение оператором остаются отдельными действиями.

Доступны индукция, обобщение, замена представления, необходимые и достаточные условия, принцип крайнего, минимальный контрпример, двойной подсчет, симметрия и усреднение, декомпозиция, контрпример и специализация. Процедура передается команде с основанием выбора; она задает порядок проверки, но не является доказательством.

Изменение цели делает ветвь устаревшей и останавливает команду. Изменение профиля до назначения блокирует запуск. Новая ветвь не сбрасывает общий бюджет. Принятие доказательства и опровержения остается решением оператора.

API: `GET /api/research-methods`, `POST /api/branches`, `POST /api/branches/{id}/commands`. Команды ветви: `prioritize`, `abandon`, `resume`. Продолжение назначенной команды выполняется через `/api/teams/{id}/commands`.

## Промежуточная проверка

Собственный исполнитель модели поддерживает `check_lean` и `check_refutation`. Инструменты задаются в профиле: [пример](../examples/profiles/model-lean.json). Среда Lean должна быть настроена на сервере.

Инструмент принимает только `source`. Цель, имя кандидата, версия, среда и модули закреплены сервером. Проверка запускается без сети: максимум четыре раза за попытку, не более 60 секунд на одну проверку. Модель получает отчет и может исправить исходник. Неудачная компиляция не доказывает ложность цели.

Записи сохраняются в `attempts/{id}/toolchecks/{probe}/report.json`. Промежуточный успех не прикрепляет доказательство и не принимает утверждение. После итогового ответа команда назначает отдельную проверку и рецензию.

Передача этих инструментов через ACP внешнему Coddy и удаленным исполнителям пока не реализована. Сервер отклоняет удаленное назначение профиля с такими инструментами. Coddy может выполнять другие роли, включая рецензию.

## Опровержение

Агент поиска контрпримеров возвращает `outcome`, `evidence` и необязательный `refutation_source`. Для исходной цели `G` сервер строит `Not G`, сохраняет связь с суммой исходной цели и использует имя `ResearchRefutation.candidate`.

Команда проверяет отрицание в Lean, назначает отдельного рецензента и останавливается на приемке. Рецензия связана с точными суммами цели и исходника. Существенные незакрытые замечания блокируют опровержение. После явного решения статус исходной цели становится `refuted`. Отрицание не прикрепляется как положительное доказательство.

API: `POST /api/refutations` из попытки; `POST /api/entities/{id}/refutation-source` для отдельного исходника; `POST /api/refutations/{id}/review`; `POST /api/refutations/{id}/accept`.

Отчет допускает обычный JSON либо один блок с меткой `json` и пояснениями снаружи. Несколько блоков, неизвестные поля и дополнительные значения JSON отклоняются. Подтвержденная команда `reprocess` повторно обрабатывает завершенные сохраненные отчеты после исправления обработчика, без повторения прежнего запроса. Следующие этапы расходуют общий бюджет.

## Память

Поиск во вкладке «Задания» различает принятую лемму, проверенное опровержение, неудачную попытку, непроверенную заметку и устаревшую запись.

Неудачный прием требует завершенной попытки текущей версии; для успешного кандидата дополнительно нужна сохраненная неудачная промежуточная проверка. Проверенный контрпример требует принятого отрицания цели. Записи содержат условия, происхождение, версии и суммы. Изменение версии переводит запись в `stale`.

Местные агенты получают до двенадцати действующих записей своей цели с уровнем доверия. Между исследованиями поиск открывает только опубликованные действующие леммы, если оператор включил соответствующий флажок. Заметки другого исследования не включаются. Поиск лексический: все слова запроса должны встретиться в записи.

При закреплении цели оператор выбирает до шестнадцати действующих модулей принятых лемм в поле `libraries`. Сервер добавляет зависимости и включает файлы в среду Lean. Исходник должен импортировать модуль; применимость и подстановка аргументов проверяются в доказательстве. Существующие обязательства не удаляются. Оспаривание леммы делает связанные результаты и ее модуль недействующими.

API: `POST /api/memory`, `GET /api/memory/search?q=...&study=...&other_studies=false`. Команды используют `expected_revision` и `request_id`; повтор той же команды не создает вторую запись.

## PostgreSQL и резервная копия

Сервер проверяет соединение перед новой транзакцией. После потери соединения он повторно получает блокировку владельца, проверяет миграции, прерывает незавершенную работу и приостанавливает новые запуски. Команда с неизвестным исходом автоматически не повторяется. Состояние доступно через `GET /api/health`.

Для согласованной копии остановите сервер и завершите попытки, проверки и сборку библиотеки. Загрузите переменную соединения с базой в окружение. Конфигурация должна использовать PostgreSQL:

```sh
go run ./cmd/research-backup -config /path/to/server.json \
  -out /var/backups/research-team/2026-10-05 \
  -compose compose.yaml -compose-env .env.postgres
```

Каталог назначения должен отсутствовать и находиться вне каталога состояния. Команда получает блокировки сервера и базы, выгружает базу, копирует обычные файлы с SHA-256, затем восстанавливает базу в отдельную временную базу и файлы в временный каталог. Она сравнивает все таблицы и скопированные файлы. Завершенный `manifest.json` записывается после успешного сравнения. Каталоги имеют права 0700, файлы 0600. Ключ входа `access-token` и файл блокировки исключены; символьные ссылки и специальные файлы запрещены.

Копия может содержать закрытые настройки, если они размещены внутри каталога состояния. Храните ее вне публичного репозитория. Частичную копию без завершенного описания использовать нельзя. Проверка восстановления не заменяет запуск восстановленного сервера: другой машине нужны конфигурация, секреты, совместимые образ и библиотеки Lean. Исторические абсолютные пути автоматически не переписываются.
