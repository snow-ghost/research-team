# Релиз v0.1.10

## Native-диагностика и библиотека

- `native.attempts` сохраняет исходник, фазу, диагностику и контрольную сумму каждой нативной попытки. Fallback-executor получает эти данные вместе с `MatchReport.Source`.
- Путь `SearchCatalog → PlanningLibraryMatch.Source → native candidate → verification` проверен на записи принятого модуля без модели.
- `research-agent -native-first -native-lean-config` использует ту же native-first обёртку, что и сервер.
- `RunCandidatePreflight` сохраняет `native` при repair: дополненный repair-контекст не запускает повторный поиск, но первоначальные попытки и диагностика не теряются.

## Слепое сравнение Research221

- Эталонный кандидат `Research221` с двумя экземплярами `sixUniqueFarOps_length` прошёл Lean с нулём модельных обращений.
- Четыре профиля использовали 8 обращений, 12251 входной и 1731 выходной токен.
- Baseline, logika и TOC прошли preflight после repair, но все три кандидата отклонены настоящим Lean. TRIZ отклонён preflight. Проверенного модельного результата нет.

## Математика

- Независимый Python BFS расширен до `r=6,n=18`. Число состояний, диаметр, flip и минимальность совпали с C++ для `n=10…18`.
- В регулярный CI входят `n=10…14`; `n=15…18` проверены офлайн.
- Общая формула диаметра `n−2` для `r=6` и макрос для `r=8` остаются открытыми.
