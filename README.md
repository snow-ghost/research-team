# Research Team

Начальная реализация исследовательской команды: исполнители заданий на Go, подключение процесса Coddy Bot через GitHub и веб-макет работы с гипотезами и леммами.

Компоненты пока работают отдельно. Веб-макет использует демонстрационные данные и не управляет действующими агентами. Результат исполнителя получает статус кандидата; автоматическая приемка доказательств не реализована.

## Состав

## Быстрый запуск

Для Go-команд нужен Go 1.26 или новее. Работа с внешними агентами и защищенным каталогом состояния рассчитана на Linux. Команды выполняются из корня репозитория.

```sh
go test ./...
go run ./cmd/research-team
go run ./cmd/research-agent -config examples/agents/model.json
```

Последняя команда проверяет профиль без запуска модели и чтения токена. Примеры содержат заменяемые адреса, модели и пути программ. `-execute` разрешает исполнение и возможные расходы поставщика. Относительный `workspace` в задании разрешается относительно файла задания.

Веб-макет, Node.js 24:

```sh
cd web-research-demo
npm ci
npm run dev -- --port 4187 --strictPort
```

Адрес: <http://127.0.0.1:4187/>. При занятом порте следует выбрать другой. Секреты и рабочие исследовательские материалы в демонстрационный интерфейс вводить не следует.

## Проверки

Используется BDD: сценарии поведения находятся в [features](features), исполняемые проверки Go в файлах `*_bdd_test.go`. Автоматического сопоставления шагов Gherkin нет.

```sh
go test -race ./...
go vet ./...
go build ./...
```

Из каталога `web-research-demo`:

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Браузерные проверки сами запускают местный сервер. `DEMO_URL` позволяет использовать уже работающий экземпляр; `CHROME_PATH` задает собственный путь браузера. GitHub Actions выполняет проверки Go, проверки модели интерфейса, сборку и браузерные сценарии без секретов поставщиков.

Для проверки настоящего Coddy Agent требуется отдельно собранный файл закрепленной версии. Испытание использует местную подстановку модели, а не оплачиваемый сервис:

```sh
CODDY_AGENT_TEST_BINARY=/path/to/coddy-agent \
  go test -race ./internal/execution -run CoddyAgentBDD -count=1
```

Порядок сборки и ограничения приведены в [инструкции Coddy Agent](integrations/coddy/AGENT.md).

## Границы реализации

- Навыки задают процедуры; права на инструменты и файлы задает программа.
- Внешний агент требует изоляции ОС и сети. `operator_managed` не создает контейнер.
- Токены передаются через окружение, а не через задание или сохраняемый профиль.
- Полный процесс Coddy Bot требует отдельного развертывания и испытания в выбранном репозитории.
- Распределенная очередь исследований, общий денежный бюджет, долговременный журнал ACP, серверная связь с интерфейсом и математическая приемка остаются задачами развития.

Публичный репозиторий содержит код, учебные данные и инструкции. Личная база знаний, настройки Obsidian, состояние исполнителей и результаты местных запусков в него не входят. [Сторонний код](THIRD_PARTY_NOTICES.md).
