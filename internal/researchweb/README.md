# Сервер Исследовательской Команды

Локальный HTTP-сервер на Go соединяет интерфейс, SQLite, исполнителей и соединитель Coddy Bot. Один процесс обслуживает одну рабочую область и одного оператора. На Linux каталог состояния защищен исключительной блокировкой. Распределенная работа и учетные записи нескольких пользователей не реализованы.

## Настройка И Запуск

Нужны Go 1.26, Linux и собранный интерфейс. Порядок сборки приведен в [корневой инструкции](../../README.md). Пример конфигурации: [examples/server/local.json](../../examples/server/local.json).

```sh
go run ./cmd/research-server -config examples/server/local.json
```

| Поле | Назначение |
|---|---|
| `listen` | Числовой локальный IP-адрес и порт; например `127.0.0.1:4187` |
| `data_dir` | Закрытый каталог состояния, вне `web_dir` |
| `web_dir` | Каталог производственной сборки интерфейса |
| `token_env` | Необязательное имя переменной с ключом входа: от 32 до 256 символов без пробелов |
| `max_parallel` | От 1 до 4 одновременно исполняемых попыток |
| `profiles` | Файлы доверенных профилей и их названия |
| `workspaces` | Разрешенные каталоги материалов: `id`, `label`, `path` |
| `allow_external_execution` | Разрешение запускать внешние программы; по умолчанию выключено |
| `coddy_config` | Необязательный путь конфигурации соединителя Coddy Bot |

Относительные пути разрешаются относительно файла конфигурации сервера. Профили и каталоги задаются оператором в файлах; браузер не может передать произвольную команду или путь.

Без `token_env` сервер создает `data_dir/access-token` с правами `0600`. В журнал попадает только путь. Ключ вводится в форму входа, после чего браузер использует временную сессию в HttpOnly cookie и отдельное значение защиты от межсайтовых запросов. Ключ не сохраняется в `localStorage`. Перезапуск сервера аннулирует браузерные сессии.

Сервер проверяет `Host` и `Origin`, ограничивает тело API-запроса 256 КиБ и принимает только известные поля JSON. Для программного клиента предусмотрен `Authorization: Bearer <ключ>`. HTML и файлы сборки доступны без входа; исследовательские данные требуют авторизации.

HTTP разрешен только на локальном адресе. Не следует открывать порт наружу или помещать сервер за публичным посредником: TLS, учетные записи, разделение полномочий и защита от распределенных атак не реализованы.

## Исполнители И Навыки

Профили повторно используют [модуль исполнения](../execution/README.md): Codex, Claude Code, OpenCode, Coddy Agent через ACP и собственный цикл обращения к совместимому API модели. В собственном профиле задаются `base_url`, `model` и `token_env`. Значение токена читается из окружения процесса, а не из задания.

Навык содержит идентификатор, версию и процедуру; набор навыков хранится в профиле. Права на инструменты и файловый доступ проверяет программа. Настройки исполнителя и доступные инструменты не выводятся из текста навыка.

Внешние программы дополнительно требуют `allow_external_execution: true` и корректный профиль с принятой оператором границей исполнения. Это разрешение не создает изоляцию. Оператор должен отдельно ограничить пользователя ОС, файловую систему, сеть, память, процессы и диск. Атрибут только для чтения у копии файлов не защищает от программы с тем же пользователем ОС.

Перед каждым запуском оператор выбирает задание, профиль и разрешенный каталог, затем подтверждает возможные расходы. Настройки по умолчанию не содержат действующих ключей и не выполняют оплачиваемые обращения.

## Попытка И Приемка

1. Команда запуска записывает попытку в очередь с версией утверждения и снимка.
2. Рабочий процесс создает отдельную копию материалов и перечень файлов с SHA-256.
3. В `input.json` сохраняются снимок, профиль без значений секретов и перечень файлов. Исполнитель получает выбранное утверждение, его основания и связанные вопросы.
4. Исполнитель возвращает результат, который записывается в `result.json`. В базе сохраняются состояние, время и контрольная сумма.
5. Оператор просматривает кандидат и направляет его на приемку. Сервер отклоняет материал, если версия цели или ее оснований изменилась.
6. Приемка требует отдельного решения с обоснованием, доступного материала и принятых действительных оснований. Существенные открытые замечания блокируют приемку.

На одно задание допускается одна попытка. Повтор той же команды с тем же идентификатором не запускает исполнителя повторно. Для новой попытки оператор создает новое задание. Изменение содержания уже обработанной команды дает конфликт.

Пауза запрещает новые запуски и извлечение из очереди; уже запущенные процессы продолжают работу. Остановка выбранной попытки отменяет ее контекст. Результат отмененной попытки не становится кандидатом.

После перезапуска незавершенные попытки получают состояние `interrupted`. Автоматического повторного исполнения нет: результат внешнего действия может быть неизвестен. Ошибка сохранения результата останавливает допуск новых операций; оператору необходимо проверить каталог и перезапустить сервер после устранения причины.

Принятая лемма применяется через отдельное обязательство переноса условий. Система сохраняет версию леммы; ее изменение или оспаривание блокирует зависимые заключения. Применение не доказывает целевую гипотезу автоматически.

Проверка происхождения различает исполнителя и оператора, но не заменяет независимых учетных записей рецензентов. Сервер не проверяет математические переходы и не интегрирован с формальным проверяющим.

## Хранение И Пределы

`research.db` содержит текущее состояние, историю снимков и идентификаторы команд. Изменение состояния, историческая запись и защита от повторной команды выполняются в одной транзакции SQLite. Каталог имеет права `0700`, база и материалы попыток закрыты для других пользователей.

В `attempts/<id>/` находятся вход, результат и копия материалов. Каталог `coddy/` содержит записи соединителя и кандидаты GitHub. Значения настроенных ключей маскируются в ответах API, но произвольные секреты в самих исследовательских материалах автоматически не распознаются.

| Предел | Значение |
|---|---|
| Размер текущего снимка | 16 МиБ |
| Утверждения, задания, вопросы, замечания | До 2000 каждого вида |
| Попытки в рабочей области | 100 |
| Копируемые материалы одной попытки | 500 файлов, 8 МиБ суммарно |
| Просматриваемые записи каталога | 2000 |
| Список истории в интерфейсе | Последние 100 событий |
| Размер базы | 65536 страниц SQLite, около 256 МиБ при странице 4 КиБ |

Символьные ссылки и специальные файлы в материалах отклоняются. `.git`, `.env`, `.env.*`, `node_modules` и каталоги состояния исключаются. Это не универсальный фильтр секретов. Для рабочих исследований используйте отдельный подготовленный каталог.

Полная история остается в базе до достижения предела; автоматической очистки и архивирования нет. Размер файловых результатов ограничивают профили, а общий предел диска оператор задает средствами ОС. Резервную копию всего `data_dir` следует делать после остановки сервера.

## Coddy Bot

Добавьте в конфигурацию сервера `"coddy_config": "../coddy/connector.json"`, предварительно настроив соответствующий файл, репозиторий и переменную токена. Подробности прав, закрепленной версии и исправления обработки рецензий находятся в [инструкции соединителя](../coddy/README.md).

Подготовка задания сохраняет локальную запись с исходным хешем Git и условиями приемки. Публикация создает задачу GitHub. Подтверждение плана разрешает Coddy исполнять его и публиковать изменения; интерфейс требует отдельного согласия и выбранного сообщения плана.

Наблюдение, ответ, замечания к строкам запроса на слияние, сбор материалов и сверка неопределенного исхода выполняются через существующий соединитель. Отправки привязаны к наблюдавшемуся состоянию GitHub. При неизвестном исходе повторная публикация блокируется до сверки.

Сервер не разворачивает Coddy Bot и не запускает его службу. Он управляет задачами уже настроенного процесса. Команда сбора получает кандидат с материалами запроса на слияние; эти материалы не исполняются и не принимаются как доказательство автоматически.

## API

Все пути имеют префикс `/api`. Мутации через браузер требуют сессии, допустимого `Origin` и `X-Research-CSRF`.

| Метод и путь | Назначение |
|---|---|
| `POST /session`, `GET /session`, `DELETE /session` | Вход, состояние сессии, выход |
| `GET /bootstrap` | Состояние, доступные профили и каталоги |
| `GET /history/{revision}` | Исторический снимок |
| `POST /actions` | Предметная команда |
| `POST /attempts` | Подтвержденный запуск задания |
| `POST /attempts/{id}/cancel` | Остановка |
| `GET /attempts/{id}` | Итоговый результат |
| `POST /coddy` | Локальная подготовка |
| `GET /coddy/{id}` | Локальная запись соединителя |
| `POST /coddy/{id}/commands` | Команда соединителя |
| `GET /coddy/{id}/candidates/{sha}` | Проверенный по SHA-256 материал |

Предметные команды и запуск содержат `expected_revision` и уникальный `request_id`. Устаревшая версия вызывает конфликт HTTP 409. Интерфейс обновляет состояние, но не повторяет действие автоматически.

Пример тела `POST /actions` для пустой рабочей области:

```json
{
  "type": "CREATE_STUDY",
  "expected_revision": 1,
  "request_id": "create-study-0001",
  "title": "Конечная проверка",
  "statement": "Точное исследуемое утверждение",
  "assumptions": "Область и предпосылки"
}
```

Схемы: `Action` в `types.go`, `RunRequest` в `service.go`, `PrepareCoddy` и `CoddyCommand` в `coddy.go`. Обновление интерфейса выполняется опросом; поток токенов и действий инструментов во время исполнения пока не передается.

## Проверка Поведения

[Сценарии BDD](../../features/research_server.feature) описывают хранение, версии, вход, изоляцию данных, отмену и отдельную приемку. Исполняемые проверки находятся в `server_bdd_test.go`. Браузерная группа `test:mvp` запускает настоящий сервер с временной базой и местными подстановками модели и GitHub.

Живой Coddy Bot, оплачиваемые модели, восстановление после физического повреждения носителя и работа под промышленной нагрузкой в этих проверках не испытываются.
