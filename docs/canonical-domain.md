# Единый предметный модуль

`research-prepare-domain` проверяет вариант организации новых целей с одним
модулем предметных определений. Это отдельное средство подготовки, а не замена
определений в действующем или принятом исследовании.

```sh
go run ./cmd/research-prepare-domain \
  -lean-config /private/lean.json \
  -spec examples/lean/domain-plan.json \
  -out /private/new-domain
```

Вход содержит `domain` и от одной до восьми `goals` типа `leancheck.Goal`.
В `domain.source` определяются функции и обозначения предметной области.
Декларация `domain.declaration` используется только для проверки определения.
Цели ссылаются на предметные имена без копирования определений.

Средство собирает предметный модуль с именем по контрольной сумме, добавляет
его импорт к каждой новой цели, собирает цели и проверяет совместные импорты.
Полученные исходники целей с явным импортом, среда, отчеты и артефакты
сохраняются в новом закрытом каталоге. Сравнивать варианты следует по этим
фактическим исходникам, времени и ошибкам сборки, а не только по числу модулей.

Подготовка доказывает лишь вспомогательные тождества `P -> P` и не устанавливает
сами цели. Обращений к модели нет. Подключение полученного каталога к рабочей
среде требует отдельного решения оператора и проверки контрольных сумм.
Исходные цели существующих исследований не меняются автоматически; их прежние
проверки нельзя переносить на новые контрольные суммы без проверки.
