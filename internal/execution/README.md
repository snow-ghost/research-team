# Исполнители исследовательских заданий

Модуль исполнения на Go. Один вызов выполняет одну ограниченную попытку и возвращает кандидат результата. Модуль используется командой `research-agent` и [HTTP-сервером](../researchweb/README.md). Хранение исследований, очередь и приемка реализованы на уровне сервера, вне этого модуля.

## Состав

- `types.go`: профиль, задание, результат, проверка настроек и фабрика `Build`.
- `model.go`: собственный цикл через API Chat Completions, вызовы разрешенного инструмента `read_file`.
- `external.go`: команды и разбор событий Codex, Claude Code и OpenCode.
- `coddy_agent.go`: прямой клиент ACP для Coddy Agent с проверкой сессии, настроек и завершения.
- `acp_process_linux.go`: двусторонний обмен с процессом ACP и ограничения потоков.
- `process_linux.go`: запуск без командной оболочки, ограничение вывода, отмена группы процессов Linux.
- `cmd/research-agent`: проверка конфигурации и отдельная команда исполнения.

Навыки передаются как процедуры с идентификатором и версией в общем пакете задания. Они не изменяют программные разрешения. Автоматическая установка навыков в каталоги внешних агентов пока отсутствует.

## Конфигурация

Примеры находятся в [examples/agents](../../examples/agents). Адрес модели содержит корень API, например `https://example.org/v1`; исполнитель добавляет `/chat/completions`. Протокол указан явно: `chat_completions`. Responses и Anthropic Messages пока не реализованы.

Пользователь задает `base_url`, токен подключения и `model`. В сохраняемом профиле вместо токена находится `token_env`, например `RESEARCH_MODEL_TOKEN`. Значение поступает из окружения процесса. Для локального сервера без авторизации поле `token_env` можно убрать. Секреты не следует помещать в задание, навыки или рабочий каталог.

Стандартное поле лимита ответа: `max_completion_tokens`. Для сервера, который поддерживает только `max_tokens`, задается `token_limit_field: "max_tokens"`. Автоматического переключения протокола и повторов запроса нет. Поддержка инструментов требуется только при непустом списке `tools`.

`max_output_tokens` ограничивает один ответ, `max_steps` ограничивает число запросов. Общий денежный бюджет и предельное число входных токенов не реализованы. При отсутствии полного учета ответ содержит `usage: null`. После сетевого сбоя расходы могут остаться неизвестными.

## Проверка и запуск

Из корня проекта проверить настройки без обращения к модели, чтения секрета и запуска внешнего агента:

```sh
go run ./cmd/research-agent -config examples/agents/model.json
```

Проверка синтаксиса не проверяет доступность сервера, модели или исполняемого файла. Примеры содержат заменяемые имена моделей и пути программ.

Команда `research-agent` разрешает относительный `workspace` относительно JSON-файла задания. Пример `task.json` поэтому переносится вместе с каталогом `workspace`. Внутренний интерфейс исполнителя по-прежнему получает абсолютный путь.

После настройки адреса, модели и серверного окружения запуск явно разрешается параметром `-execute`:

```sh
go run ./cmd/research-agent \
  -config examples/agents/model.json \
  -task examples/agents/task.json \
  -execute
```

Запуск может вызвать расходы поставщика модели. Секрет не передается аргументом команды. `SIGINT` и `SIGTERM` отменяют текущую попытку.

Для внешнего агента выбирается `codex.json`, `claude.json`, `opencode.json` или `coddy-agent.json`. Перед исследованием проверяется точное совпадение версии. Версии текущих адаптеров:

| Агент | Строка версии |
|---|---|
| Codex | `codex-cli 0.155.1` |
| Claude Code | `2.1.274 (Claude Code)` |
| OpenCode | `1.2.27` |
| Coddy Agent | `1.1.64`, `1.2.1`, `1.2.54`; профиль закрепляет одну версию |

Изменение версии требует проверки команды, разрешений и событий, затем обновления адаптера и испытаний. Поддержка OpenCode 2 не заявляется.

`coddy` обозначает [coddy-project/coddy-bot](https://github.com/coddy-project/coddy-bot), координатор задач разработки с собственными исполнителями ACP. Прямой профиль возвращает `ErrWorkflowRequired` вместе с `ErrUnsupported` до создания исполнителя и чтения секретов. Выбранный полный процесс реализован через отдельный [соединитель GitHub](../coddy/README.md); он не использует этот синхронный интерфейс.

## Границы защиты

Для Coddy Agent применяется [отдельная инструкция](../../integrations/coddy/AGENT.md): адрес API и модель задаются в `external`, токен через `secret_env`. `max_steps` ограничивает обороты цикла агента, `max_output_tokens` задает предел ответа модели; ненулевой `max_tool_calls` отклоняется. Принимается только `end_turn` с текстом; ограниченный ответ не становится кандидатом. Автоматический поиск навыков, встроенная память и вложенные агенты отключены.

Конфигурацию создает доверенный оператор. Поля `executable`, `search_path` и `base_url` нельзя принимать непосредственно из ответа модели или от непривилегированного пользователя веб-интерфейса.

Внешние процессы требуют подготовленной оператором изолированной среды. Значение `execution_boundary: "operator_managed"` фиксирует это требование, но не создает контейнер и не проверяет его наличие. Без внешней изоляции процесс обладает правами пользователя ОС.

Адаптер создает отдельный временный домашний каталог, передает только перечисленные ключи подключения, использует стандартный ввод для задания и не включает режимы обхода разрешений. Текущие команды ориентированы на чтение. Запись файлов, запуск опытов и произвольная командная оболочка не предоставлены как настраиваемые возможности этой версии.

Разрешения самого агента не заменяют ограничение файловой системы и сети. Настройки проекта и расширения внешней программы также требуют проверки. Каталог задания должен содержать только разрешенные материалы и не разделяться между пишущими исполнителями. Для OpenCode 1 применяется его формат `permission`; другие версии могут иметь иную схему.

Собственный `read_file` ограничен корнем каталога через `os.Root`, отклоняет выходящие ссылки и специальные файлы, читает до 64 КиБ. Это ограничение доступа, а не неизменяемый снимок: материалы необходимо закреплять отдельно. Поддержка этого инструмента и внешних процессов реализована для Linux.

HTTP допускается только по явной настройке для числового адреса обратной связи. Остальные адреса требуют HTTPS. Собственный клиент модели не выполняет перенаправления; сеть внешнего агента ограничивает оператор. В многопользовательской системе дополнительно нужен список разрешенных адресов и сетевые ограничения, включая защиту от обращения к внутренним службам. Этот модуль не является публичным сетевым шлюзом.

Тела ошибок поставщиков и стандартный поток ошибок внешних программ не выводятся. Точные значения переданных ключей маскируются в конечном тексте. Это не гарантирует удаления произвольных секретов из исходных материалов или преобразованных значений.

При отмене внешнего процесса группе Linux посылается `SIGKILL`. Процессы, сменившие группу или сеанс, должен останавливать внешний управляющий процесс через контейнер или группу ресурсов. Отмена местного процесса не удостоверяет отмену запроса у поставщика.

## Статус проверки

`--help` и `--version` проверены у установленных программ; реальные запросы к поставщикам не выполнялись. Испытания используют местные HTTP-серверы и подставные исполняемые файлы. Совместимость полного обмена с учетной записью поставщика еще требует отдельного испытания.

Coddy Agent дополнительно собран из закрепленных исходников и испытан через ACP против местной подстановки модели. Повтор: `CODDY_AGENT_TEST_BINARY=/путь/к/coddy-agent go test -race ./internal/execution -run CoddyAgentBDD -count=1`. Без переменной испытание настоящего файла пропускается; проверки подставного ACP-сервера выполняются всегда.

`features/agent_execution.feature` описывает поведение. Исполняемые проверки реализованы через стандартный `testing` в файлах `*_bdd_test.go`; автоматического сопоставления шагов Gherkin нет.

```sh
go test -race ./...
go vet ./...
```

Остаются за пределами реализации: выдача заданий нескольким работникам, защита от устаревшего владельца в хранилище, поток событий в браузер, долговременное хранение полных траекторий, восстановление сеансов, денежные квоты, формальная проверка, разрешаемые операции записи и вычислений. Поле `lease_epoch` переносится без изменения, но его актуальность обязан проверить координатор.
